# Reference and recovery material

These are separate examples, not the learner's generated feature artifacts and
not a completed application. The working app on `spec-workshop` deliberately
remains the unfinished starter.

| Artifact | Use |
| --- | --- |
| [Example specification](spec.md) | Compare scope and acceptance criteria when your specification is unclear |
| [Example implementation plan](plan.md) | Check that a plan addresses the actual app and avoids infrastructure |
| [Example task breakdown](tasks.md) | Recover a missing work item or overly broad task |

Keep reference files here. Have Spec Kit generate the active feature directory;
do not copy these files over another learner's work or treat this directory as
the active feature. Active artifacts must reflect the participant's actual
choices, implementation, and evidence.

## Nondestructive recovery

1. Keep your current checkout and files intact.
2. Read only the reference artifact for the checkpoint where you are blocked.
3. Ask Copilot to reconcile your active artifact with the approved contract, and
   review the proposed changes yourself before proceeding.
4. If your checkout is unusable, make a separate clone of the repository, check
   out `spec-workshop`, complete prework, and repeat the initialization and
   constitution checkpoint there. Do not reset or clean your original checkout.
5. Do not copy an authentication token, environment file, or member data into a
   recovery checkout.

There is no claimed completed-solution checkpoint or recorded full workshop
rehearsal in this branch. Facilitators should create and verify any additional
recovery artifacts they need before publishing them as working solutions.
